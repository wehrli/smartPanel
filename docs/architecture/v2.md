# smartPanel v2 architecture: the contract for parallel work

Read this before touching v2 code. It fixes the module layout, who owns which files, the
shared state, and the rules. The backlog (`docs/backlog/`) says *what* to build; this
says *where* and *how*. The design is `docs/design/prototype.html`.

## Decisions (answers to D1 to D3 in the backlog)

- **D1: fully GTK4, one process.** `libayatana-appindicator` is GTK3-only, and PyGObject
  can't load GTK 3 and 4 together. So we **drop it and speak the tray protocols ourselves**
  over `Gio.DBus`: StatusNotifierItem (`org.kde.StatusNotifierItem`) for the panel item,
  and `com.canonical.dbusmenu` for its menu. Neither needs GTK. The Ubuntu AppIndicator
  extension reads the text label from the SNI property `XAyatanaLabel` (verified in
  `/usr/share/gnome-shell/extensions/ubuntu-appindicators@ubuntu.com/appIndicator.js`).
  The dashboard and palette are GTK4 + libadwaita (`gir1.2-adw-1`, present on this box).
- **D2: coloured graphics in the bar without an extension.** That extension keeps a
  *wide* icon's aspect ratio when the SNI `IconName` is an **absolute path to an image file
  ≥ 1.5× wider than tall, inside a user-writable dir** (`_loadCustomImage`, "Hello
  indicator-multiload!"). Pixmap icons are forced square, so they aren't used.
  We render the A6 strip and A4 graphs with **pycairo** to
  `$XDG_RUNTIME_DIR/smartpanel/bar-<hash>.png` and point `IconName` at it. A new file name
  per distinct image defeats the texture cache. The A1/A5 text goes in `XAyatanaLabel`.
- **D3: the desktop HUD is a separate GNOME Shell extension**, `smartpanel-hud@omdev.dev`
  (GJS, ESM, shell-version 50). It draws on the background layer and reads state over
  our D-Bus API. It's optional: everything else works without it.

## Process model

```
smartpanel (python, Adw.Application "dev.omdev.SmartPanel", held, no window at start)
 ├─ collectors  → Store (state/)          GLib timeouts; slow work on threads → idle_add
 ├─ services    → Store + Events          sessions control, spend aggregator, journal
 ├─ tray/       ← Store                   SNI + DBusMenu over Gio, wide PNG bar icon
 ├─ ui/         ← Store, → Actions        GTK4/Adw window, palette, dialogs, toasts
 └─ dbus/       ← Store, → Actions        dev.omdev.SmartPanel1 (panel1.xml)
extension/smartpanel-hud@omdev.dev  ← D-Bus  (separate, GJS)
```

Single instance and CLI verbs come from `Gio.Application` itself: a second
`smartpanel --palette` / `--dashboard sessions` / `--hud toggle` is forwarded to the
running instance through `HANDLES_COMMAND_LINE`. No hand-rolled IPC.

## Shared contract (already written, do not change without updating every user)

- `smartpanel/state/model.py`: every field any surface shows. **Read it fully.**
- `smartpanel/state/store.py`: `Store.update/replace/mutate/batch/emit/toast/to_json`.
- `smartpanel/state/actions.py`: the `Actions` protocol, implemented by
  `services/controller.py` (real) and `demo/controller.py` (simulated).
- `smartpanel/dbus/panel1.xml`: the D-Bus API.

If your work package genuinely needs a new state field, **add it to `model.py` with a
default** in your branch and mention it in your report. Integration merges these. Never
rename or remove a field.

## Rules

- The GLib main loop budget is **< 50 ms per callback**. Anything slower (aggregator scan,
  journal, prompt-answer confirmation) runs on a thread and hands results back with
  `GLib.idle_add`. **Only the main thread mutates the Store.**
- Sensors and services **never raise** into the loop; log and degrade to `None`.
- GTK-free modules (`state`, `config`, `history`, `collect` logic, `commands`,
  `tray/barspec`, `tray/menu`, `tray/dbusmenu` layout code, `sessions/*`,
  `claude_stats/*`, `ui/charts` geometry) must be unit-testable without a display.
- Tests use real fixtures (pane captures, JSONL lines), not mocks of our own parsers.
- No real side effects in tests: no tmux, no terminals, no notifications, no writes outside
  `tmp_path`.
- **Test command:** `/tmp/claude-1000/-home-user-dev-omdev-smartPanel/cd974ae2-84aa-4091-bff1-dba5eb005ce7/scratchpad/venv/bin/python -m pytest -q`
  (Python 3.14 with system `gi`, pytest, psutil, PyYAML). The repo's `.venv` is broken; don't use it.
- GTK smoke checks: the session has a Wayland display. You may run a window for a couple
  of seconds to check it builds (`timeout 5 python -m smartpanel --demo busy --dashboard overview`),
  but never leave processes running, and **never touch the user's running
  `smartpanel.service`**.
